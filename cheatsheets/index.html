Explicit, non-destructive examples for authorized security testing and defensive research. They contain no real credentials, secrets, or live-target instructions. Run them only against systems you own or have written permission to test. Maintained by Sami Mirov — OakFort.

Notes

  • Use this as a checklist for context isolation, tool allowlists, output validation, rate limits, and audit logging.
  • Expected behavior is to refuse hidden-instruction disclosure, treat retrieved text as data, and require confirmation before consequential tool calls.
  • Pair every offensive test with a detection signal, a safe expected result, and a regression test.
